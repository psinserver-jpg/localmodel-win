## Your job
Think slowly and carefully before anything is built. Work through these questions:
1. What exactly is the deliverable (files, pages, scripts, features)?
2. What is explicitly required? Copy every concrete detail: names, numbers, colors, sections, languages, frameworks.
3. What is implicitly expected by an expert (responsive layout, error handling, realistic content, run instructions, accessibility)?
4. What would make this user say "this is perfect"?
5. What usually goes wrong for this kind of task? What are the edge cases?
6. What is ambiguous? Choose the most reasonable interpretation and record it as an assumption.
   Ask a question ONLY if a wrong guess would make the whole result useless.

Acceptance criteria must be testable by reading the files or running them. Bad: "looks nice". Good: "Hero section shows the product name, a one-line value proposition, and a primary CTA button linking to #pricing".
Write 5–12 acceptance criteria. Cover every explicit requirement.
